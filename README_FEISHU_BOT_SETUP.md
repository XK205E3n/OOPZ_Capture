# 从零配置 OOPZ 飞书机器人

本文用于在一个新的飞书租户中，从零创建并接入 OOPZ Capture 的飞书机器人。完成后，机器人将能够：

- 在唯一的受控群内接收被 `@` 的指令，并发送文本、交互卡片、Markdown 与 PDF 文件；
- 通过卡片接收“分析、发布、撤回、删除”等确认操作；
- 将获准公开的报告创建为飞书新版文档，设为“持链接可读”，并写入多维表格索引；
- 在删除会话时删除其创建的公开文档和对应的多维表格记录；
- 自动把首次邀请它进入的群绑定为唯一控制群。

这不是“开通飞书所有权限”的指南。应用只应获得当前代码实际调用的 **11 项应用身份（tenant）权限**；扩大到 `drive:drive`、`bitable:app`、`im:message` 等广泛权限既没有必要，也会增加误操作和审查成本。

> 本项目使用飞书官方 `lark-oapi` 的**长连接**接收事件。本机或服务器主动连到飞书，因此不需要公网 Webhook 地址、域名或入站端口。

## 0. 先理解三个不同层面的授权

这三个概念经常被混淆，必须分别完成：

| 层面 | 在哪里设置 | 解决的问题 | 本文的步骤 |
| --- | --- | --- | --- |
| 应用 API 权限 | 飞书开放平台 → 应用 → 权限管理 | 应用可否调用消息、文档、Base 等 API | [第 4 节](#4-开通当前代码所需的全部应用权限) |
| 资源协作者权限 | 报告文件夹和多维表格本身 | 应用可否操作**这个指定的**文件夹/Base | [第 7 节](#7-将应用加入报告文件夹和-base-的协作者) |
| 群成员资格 | 飞书客户端中的控制群 | 机器人能否加入群、接收 `@` 指令及回复 | [第 8 节](#8-将机器人加入控制群并自动绑定) |

即使 API 权限全部显示“已开通”，没有把应用添加到目标文件夹和 Base 的协作者中，写入仍会失败。反过来，把机器人拉进群也不会自动授予文档或 Base 权限。

## 1. 准备条件

- 你拥有该飞书租户中创建、配置和发布自建应用的权限；若发布需要企业管理员审核，请先安排该审批人。
- OOPZ Capture 已在 Windows 开发机或服务器上安装。详见项目 [README](README.md) 和 [部署说明](docs/DEPLOYMENT.md)。
- 运行机器能出站访问飞书；长连接模式不要求公网可访问。
- 计划好一个专用的“控制群”。该群内**所有成员拥有相同的控制权限**，可以录音、分析、发布、撤回和删除；请勿把不应拥有这些权限的人加入其中。
- 若要启用公开发布，事先准备一个报告目标文件夹和一个多维表格（Base）。这两者可以稍后创建，但必须在首次发布前完成协作者授权。

## 2. 创建企业自建应用并启用机器人

1. 打开 [飞书开放平台](https://open.feishu.cn/)，登录拥有应用管理权限的账号。
2. 进入“开发者后台” → “创建企业自建应用”（页面措辞可能随平台更新略有变化）。
3. 填写名称，例如“`OOPZ 管理机器人`”，添加清晰的图标与说明后创建。
4. 在左侧“应用能力”中进入“添加应用能力”，启用“机器人”。
5. 进入“机器人”页面，设置机器人名称与头像。不要在这里配置普通 HTTP 回调地址；本项目采用长连接。
6. 在“凭证与基础信息”中复制 `App ID` 和 `App Secret`。`App Secret` 只写入运行机器的 `.env`，不要发到群聊、截图、提交 Git 或写入本文档。

## 3. 配置事件和卡片回调（长连接）

在“开发配置” → “事件与回调”中，完成以下两类配置。它们在平台中是不同区域，缺一不可。

### 3.1 事件配置：接收群指令与首次入群

在“事件配置”中选择“使用长连接接收事件”，然后添加：

| 事件 | 事件代码 | 用途 |
| --- | --- | --- |
| 接收消息 v2.0 | `im.message.receive_v1` | 接收控制群内 `@机器人` 后的文字指令 |
| 机器人被加入群 | `p2.im.chat.member.bot.added_v1` | 当控制群 ID 为空时，自动绑定机器人首次被邀请进入的群 |

`im.message.receive_v1` 是普通消息事件；本项目会在本地再次检查群 ID 和 `@` 提及，因此不会处理群外消息、私聊消息或未提及机器人的群消息。

### 3.2 回调配置：接收交互卡片点击

在同一页面的“回调配置”中：

1. 点击“订阅方式”，选择“使用长连接接收回调”。
2. 点击“添加回调”。
3. 在“卡片”分类勾选 **卡片回传交互**：`card.action.trigger`。
4. 保存。

不要选择旧的“消息卡片回传交互” `card.action.trigger_v1`。本项目监听的是 `card.action.trigger`，用于“开始/暂不分析”“批准/不发布”“撤回”“确认删除”等按钮。

## 4. 开通当前代码所需的全部应用权限

进入“权限管理”。全部选择**应用身份权限**（即 `tenant_access_token`），不需要用户身份 `user_access_token` 权限。

当前应用已使用的完整权限清单如下，共 11 项。可按权限码搜索，也可用“批量导入/导出权限”功能导入第一个代码块的 JSON。

```json
{
  "scopes": {
    "tenant": [
      "im:message.group_at_msg:readonly",
      "im:message:send_as_bot",
      "im:resource",
      "im:chat.members:read",
      "docx:document:create",
      "docx:document:write_only",
      "docs:permission.setting:write_only",
      "space:document:delete",
      "base:record:create",
      "base:record:update",
      "base:record:delete"
    ],
    "user": []
  }
}
```

| 权限码 | 平台中通常显示的名称 | OOPZ 的实际用途 |
| --- | --- | --- |
| `im:message.group_at_msg:readonly` | 获取群组中用户 @ 机器人消息 | 接收控制群内的文字指令；不读取群内所有消息。 |
| `im:message:send_as_bot` | 以应用身份发消息 | 向控制群发送状态、文本、普通交互卡片和文件消息。 |
| `im:resource` | 获取与上传图片或文件资源 | 上传内部 Markdown 与候选 PDF，并发送至控制群。 |
| `im:chat.members:read` | 查看群成员 | 将审批人的 `open_id` 解析为其在控制群的显示名，写入公开索引。 |
| `docx:document:create` | 创建新版文档 | 批准发布后，在指定文件夹创建公开报告文档。 |
| `docx:document:write_only` | 编辑新版文档 | 写入报告正文；刷新已发布报告时替换正文块。 |
| `docs:permission.setting:write_only` | 修改云文档权限设置 | 发布时设为“持链接可读”，撤回时关闭外部访问。 |
| `space:document:delete` | 删除云空间文件夹和云文档 | 永久删除该应用创建的公开报告文档。 |
| `base:record:create` | 新增记录 | 在公开报告 Base 索引中增加发布记录。 |
| `base:record:update` | 更新记录 | 撤回报告时把索引状态改为“已撤回”。 |
| `base:record:delete` | 删除记录 | 永久删除对应的 Base 索引记录。 |

### 不要为了“方便”额外开通的权限

以下权限不是当前实现所需，尤其不要用宽泛权限替代上述最小权限：

- `drive:drive`、`bitable:app`：覆盖范围过大；当前代码已有精确的文档和记录权限。
- `im:message`、`im:message:readonly`、`im:message.group_msg`：项目只接收 `@机器人` 的指令，不应读取整个群聊。
- `im:message.p2p_msg:readonly`：本项目禁用私聊控制。
- `im:chat`、`im:chat:create`、`im:chat:delete`、`im:chat:operate_as_owner`：机器人不创建、搜索、管理或解散群聊；由人手动邀请进控制群。
- `cardkit:card:write`：项目发送普通消息卡片 JSON，未使用 CardKit 卡片实体 API。

## 5. 创建并发布应用版本

权限、机器人能力和事件配置通常不会立即对已发布应用生效。配置完成后：

1. 进入“版本管理与发布”。
2. 创建新版本，填写版本号和变更说明，例如“启用 OOPZ 群控制、长连接事件与报告发布权限”。
3. 申请发布；如租户要求管理员审核，完成审核。
4. 回到权限管理，确认上述 11 项均显示“已开通”，并确认版本页面没有待发布变更。

新建应用若未发布，常见表现是：飞书客户端搜索不到机器人、无法将它邀请入群，或本机连接成功但没有收到任何事件。

## 6. 建立公开报告文件夹与 Base 索引（可选，但发布/删除必需）

如果只需要群内控制、转写、分析与文件投递，可暂不配置本节；一旦配置以下四个环境变量，OOPZ 就会启用“批准发布 → 公开文档 → Base 索引”链路。

### 6.1 创建报告文件夹

在飞书云空间新建一个专用文件夹，例如“`OOPZ 公开报告`”。机器人发布时将在其中创建新版文档。请勿把该文件夹的普通成员权限直接设为互联网公开；公开性由程序对每一份获批准的报告单独控制。

从文件夹链接或其“复制链接”入口取得 `folder_token`，填入：

```text
OOPZ_FEISHU_PUBLIC_FOLDER_TOKEN=<folder_token>
```

### 6.2 创建 Base 与数据表

新建一份多维表格，例如“`OOPZ 公开报告索引`”，再创建（或保留）一张数据表。当前代码写入下列字段；字段名必须完全一致：

| 字段名 | 推荐类型 | 用途 |
| --- | --- | --- |
| 报告标题 | 文本 | 报告显示名称 |
| 录音日期 | 日期时间 | 录音开始时间 |
| 发布时间 | 日期时间 | 创建公开报告的时间 |
| 状态 | 单选或文本 | `已发布`、`已撤回` |
| 对外摘要 | 多行文本 | 公开报告前 1000 个字符以内的摘要 |
| 阅读链接 | 超链接 | 公开报告链接 |
| 审批人 | 文本 | 批准发布的群成员显示名 |

从 Base 链接中取得：

- `app_token`：整份多维表格的标识，填写 `OOPZ_FEISHU_BASE_APP_TOKEN`；
- `table_id`：其中目标数据表的标识，填写 `OOPZ_FEISHU_BASE_TABLE_ID`。

两者不是同一个值。另复制该 Base 对外提供的稳定 HTTPS 链接，填写 `OOPZ_FEISHU_PUBLIC_INDEX_URL`。如果索引本身要供外部读者访问，还需要在飞书界面按你们的组织策略打开它的分享范围；程序不会代替你公开整个 Base。

## 7. 将应用加入报告文件夹和 Base 的协作者

这一步授权的是**资源**，不是开放平台的 API。必须在应用已发布后操作，否则搜索结果中可能找不到它。

### 7.1 报告文件夹

1. 打开“`OOPZ 公开报告`”文件夹。
2. 进入“共享/协作者”或“更多 → 添加文档应用”（具体入口取决于飞书客户端版本）。
3. 搜索自建应用名称，例如“`OOPZ 管理机器人`”。
4. 添加后将权限设为 **可管理**（至少应允许在该文件夹创建、编辑和删除机器人创建的文档）。
5. 保存后重新打开协作者列表，确认应用仍在列表中。

### 7.2 Base 索引

1. 打开“`OOPZ 公开报告索引`”多维表格。
2. 点击右上角“…” → “更多” → **添加文档应用**。不要只在普通“添加协作者”窗口搜索人员。
3. 搜索并添加“`OOPZ 管理机器人`”。
4. 授予 **可编辑** 权限。
5. 确认选中的是含目标 `table_id` 的那份 Base，而不是同名副本或 Wiki 中的其他节点。

## 8. 将机器人加入控制群并自动绑定

### 8.1 启动前配置

将 [`.env.example`](.env.example) 复制为 `.env`，并至少填写飞书应用凭据。不要把 `.env` 提交到 Git。

```text
# 飞书机器人：启动必填
OOPZ_FEISHU_APP_ID=cli_xxx
OOPZ_FEISHU_APP_SECRET=xxx

# 飞书机器人：控制群 ID
# 保持为空以启用首次入群自动绑定。
OOPZ_FEISHU_ADMIN_CHAT_ID=

# 公开发布与索引：若启用第 6 节，则四项都必须填写。
OOPZ_FEISHU_PUBLIC_FOLDER_TOKEN=
OOPZ_FEISHU_BASE_APP_TOKEN=
OOPZ_FEISHU_BASE_TABLE_ID=
OOPZ_FEISHU_PUBLIC_INDEX_URL=
```

同时按 `.env.example` 填写 OOPZ 登录信息和分析器 API Key。完整变量含义见项目主 README；本文不记录实际 App Secret、账号密码、Base token 或群 ID。

### 8.2 首次自动绑定（推荐）

1. 确认 `OOPZ_FEISHU_ADMIN_CHAT_ID` 为空。
2. 启动项目根目录的 [启动OOPZ全流程.bat](启动OOPZ全流程.bat)，或在已激活虚拟环境中运行：

   ```powershell
   .\.venv\Scripts\oopz-feishu.exe serve
   ```

3. 在飞书客户端打开计划作为控制入口的群聊。
4. 通过群成员/群设置的“添加机器人”入口搜索已发布的机器人并邀请加入；确保它可以在群中发言。
5. 程序收到 `p2.im.chat.member.bot.added_v1` 后，会校验群 ID 并把首次加入的群 ID 原子写入 `.env` 的 `OOPZ_FEISHU_ADMIN_CHAT_ID`。
6. 网关随即只监听这个群。之后将机器人邀请到其他群不会覆盖该值。

自动绑定只在变量为空时发生，目的是防止任意群通过一次邀请夺取控制权。若需迁移控制群，应在本机停止网关、手动修改 `.env` 中的群 ID（或清空它以重新执行首次绑定）、再重启；不要尝试在群内用命令修改控制群。

### 8.3 已错过首次入群事件时的兼容方法

如果机器人已经在目标群里，因而无法再次触发“被加入群”事件：

```powershell
.\.venv\Scripts\oopz-feishu.exe discover-ids
```

随后在目标群发送 `@机器人 帮助`。终端会打印 `OOPZ_FEISHU_ADMIN_CHAT_ID=oc_...`；把该值写到本机 `.env` 后停止兼容命令，正常启动 `serve`。`discover-ids` 只用于发现 ID，不执行录音或发送业务消息。

## 9. 验收清单

按以下顺序检查，能较快区分配置、资源授权和业务本身的问题：

1. 进程日志出现“飞书长连接已就绪”。
2. 在控制群发送 `@机器人 帮助`：机器人应回复帮助；在私聊、其他群或不 `@` 的情况下不应触发。
3. 点击一张测试卡片按钮：确认卡片回调能抵达本机；如果点击无响应，优先检查 `card.action.trigger` 和回调方式是否均为长连接。
4. 运行一次短录音，确认文字状态、内部 Markdown 和 PDF 能投递到控制群。
5. 若启用公开发布：批准一份不含敏感信息的测试报告，确认目标文件夹出现新版文档、文档链接可打开、Base 出现一条“已发布”记录。
6. 测试撤回，确认文档不再对外可读，Base 状态变为“已撤回”。
7. 仅在可接受永久删除时测试删除：确认公开文档与 Base 记录先被删除，再删除本地 Session。删除不可由本程序恢复。

## 10. 常见故障

| 现象 | 优先检查 |
| --- | --- |
| 机器人搜不到或无法加入群 | 应用是否已发布、可用范围是否包含当前账号、机器人能力是否启用。 |
| 本机显示已连接，但群里 `@` 它没有反应 | `im.message.receive_v1` 是否已添加；是否选择长连接；是否发送到唯一绑定群；是否确实 `@` 机器人。 |
| 文字能收发，卡片按钮无响应 | “回调配置”是否选择长连接并订阅 `card.action.trigger`；不要用旧的 `_v1` 回调。 |
| 能创建文档但无法写入目标文件夹/Base | 这是资源协作者问题：按 [第 7 节](#7-将应用加入报告文件夹和-base-的协作者) 将应用加入指定文件夹和 Base，不要只检查 API 权限。 |
| 删除文档报 `99991672` | 缺少 `space:document:delete`，或开通后未发布新版本。 |
| 删除 Base 记录报 `99991672` | 缺少 `base:record:delete`，或应用没有目标 Base 的可编辑权限。 |
| Base 写入失败或写错表 | 区分 `OOPZ_FEISHU_BASE_APP_TOKEN`（Base）与 `OOPZ_FEISHU_BASE_TABLE_ID`（数据表）；同时核对字段名和类型。 |
| 自动绑定到了不该使用的群 | 停止网关，本地修正 `.env` 的 `OOPZ_FEISHU_ADMIN_CHAT_ID`，再重启。首次绑定之后不会自动替换。 |

## 11. 安全与运维边界

- App Secret、OOPZ 登录凭据、分析 API Key、群 ID、Base token 和文件夹 token 都属于运行配置；只保存在 `.env` 或服务器的受保护配置目录中。
- 本项目只将一个群设为控制群，但不在群内划分管理员角色。控制群成员的操作权限相同。
- 公开发布由群内卡片批准触发；未批准的报告仅在控制群内投递。
- 应用更新、权限变更后始终创建/发布新版本，并重启网关以便验证。
- 生产环境的 `.env`、输出、飞书状态和日志属于持久数据，遵守 [部署状态基线](docs/DEPLOYMENT_STATE.md) 的目录与发布规则；不要在服务器版本目录中手改代码或配置。
