# OOPZ 飞书机器人：一键配置与手动保底

本文用于在一个新的飞书租户中，从零创建并接入 OOPZ Capture 的飞书机器人。完成后，机器人将能够：

- 在唯一的受控群内接收被 `@` 的指令，并发送文本、交互卡片和图片；
- 通过卡片接收"选择语音频道、确认录音、选择待分析录音、确认删除"等操作；
- 把录音后自动生成的精华图发到该群；
- 自动把首次邀请它进入的群绑定为唯一控制群。

应用只需要 **3 项应用身份（tenant）权限**（见第 3 节）。机器人不创建文档、不写多维表格，因此不要为了"方便"开通 `drive:drive`、`bitable:app`、`im:message` 这类广泛权限。

> 本项目使用飞书官方 `lark-oapi` 的**长连接**接收事件。本机或服务器主动连到飞书，因此不需要公网 Webhook 地址、域名或入站端口。

## 首选：一键创建或更新机器人

**正常配置从这里开始，不需要先执行后面的手动创建步骤。** 完成项目依赖安装并创建 `.env` 后，在项目目录运行：

```bash
oopz-feishu setup
```

1. 使用有应用管理权限的飞书账号，扫描终端二维码并在飞书 App 中确认。远程终端无法显示二维码时，加 `--url-only` 打开生成的确认链接。
2. 程序自动创建或更新应用、申请 3 项应用身份权限，配置长连接事件及 `card.action.trigger` 回调，并将 App ID/Secret 写入当前 `.env`；Secret 不显示在终端。已有 App ID 时默认更新该应用；只有明确切换到另一应用时才使用 `--force`。
3. 若开放平台提示待发布版本，按[第 4 节](#4-创建并发布应用版本)完成发布或管理员审批。扫码成功不代表租户审批已自动完成。
4. 启动程序，将机器人邀请进目标控制群，按[第 5 节](#5-将机器人加入控制群并自动绑定)自动绑定，再完成[第 6 节验收](#6-验收清单)。

服务器首次安装见 [部署指南](docs/DEPLOYMENT.md)。

只有一键流程失败、租户不支持或受管理员策略限制时，才使用下面的手动保底（第 1–3 节）。已经成功一键配置的应用无需重复创建，只在排障时对照权限和事件清单。

## 1. 创建企业自建应用并启用机器人

1. 打开 [飞书开放平台](https://open.feishu.cn/)，登录拥有应用管理权限的账号。
2. 进入"开发者后台" → "创建企业自建应用"，填写名称，例如"`OOPZ 管理机器人`"。
3. 在"应用能力"中启用"机器人"，设置机器人名称与头像。不要配置普通 HTTP 回调地址；本项目采用长连接。
4. 在"凭证与基础信息"中复制 `App ID` 和 `App Secret`。`App Secret` 只写入运行机器的 `.env`，不要发到群聊、截图或提交 Git。

## 2. 配置事件和卡片回调（长连接）

在"开发配置" → "事件与回调"中完成两类配置，缺一不可。

**事件配置**：选择"使用长连接接收事件"，添加：

| 事件 | 事件代码 | 用途 |
| --- | --- | --- |
| 接收消息 v2.0 | `im.message.receive_v1` | 接收控制群内 `@机器人` 后的文字指令 |
| 机器人被加入群 | `p2.im.chat.member.bot.added_v1` | 控制群 ID 为空时，自动绑定机器人首次被邀请进入的群 |

本项目在本地再次检查群 ID 和 `@` 提及，不会处理群外消息、私聊消息或未提及机器人的群消息。

**回调配置**：订阅方式选"使用长连接接收回调"，添加"卡片"分类下的 **卡片回传交互** `card.action.trigger`。不要选旧的 `card.action.trigger_v1`。

## 3. 开通所需的应用权限

进入"权限管理"，全部选择**应用身份权限**（`tenant_access_token`），不需要用户身份权限：

| 权限码 | 平台中通常显示的名称 | OOPZ 的实际用途 |
| --- | --- | --- |
| `im:message.group_at_msg:readonly` | 获取群组中所有 @ 机器人的消息 | 接收群内 @ 机器人的指令 |
| `im:message:send_as_bot` | 以应用的身份发消息 | 发送文本、卡片和图片 |
| `im:resource` | 获取与上传图片或文件资源 | 上传精华图后以图片消息发出 |

## 4. 创建并发布应用版本

权限、机器人能力和事件配置通常不会立即对已发布应用生效。配置完成后在"版本管理与发布"创建新版本并申请发布；如租户要求管理员审核，完成审核。回到权限管理确认 3 项均显示"已开通"，并确认版本页面没有待发布变更。

新建应用若未发布，常见表现是：飞书客户端搜索不到机器人、无法将它邀请入群，或本机连接成功但没有收到任何事件。

## 5. 将机器人加入控制群并自动绑定

将 [`.env.example`](.env.example) 复制为 `.env`，至少填写飞书应用凭据、OOPZ 登录信息和 `OOPZ_ANALYZER_*`；`OOPZ_FEISHU_ADMIN_CHAT_ID` 留空以启用首次入群自动绑定。不要把 `.env` 提交到 Git。

1. 在已激活的虚拟环境中运行（服务器上由部署流程管理）：`oopz-feishu serve`。
2. 在飞书客户端打开计划作为控制入口的群，添加已发布的机器人。
3. 程序收到 `p2.im.chat.member.bot.added_v1` 后，校验群 ID 并把首次加入的群 ID 原地写入 `.env` 的 `OOPZ_FEISHU_ADMIN_CHAT_ID`。之后把机器人邀请到其他群不会覆盖它。

自动绑定只在变量为空时发生，目的是防止任意群通过一次邀请夺取控制权。迁移控制群时，在本机停止网关、手动修改 `.env` 中的群 ID（或清空它重新首次绑定）再重启；不要尝试在群内用命令修改。

如果机器人已经在目标群里，无法再触发入群事件：运行 `oopz-feishu discover-ids`，随后在目标群发送 `@机器人 帮助`，终端会打印 `OOPZ_FEISHU_ADMIN_CHAT_ID=oc_...`；把该值写进 `.env`、停止兼容命令，再正常启动 `serve`。`discover-ids` 只用于发现 ID，不执行录音或发送业务消息。

## 6. 验收清单

1. 进程日志出现"飞书长连接已就绪"。
2. 在控制群发送 `@机器人 帮助`：机器人应回复帮助；在私聊、其他群或不 `@` 的情况下不应触发。
3. 发送 `@机器人 开始录音 1分钟` 并点击卡片按钮：确认卡片回调能抵达本机；点击无响应时，优先检查 `card.action.trigger` 和回调方式是否均为长连接。
4. 录音结束并转写后，群里应在几分钟内收到一张图（只有图，没有文字）。分析失败时应收到一条带原因的文字，并能用 `待分析` 重试。
5. `最近图片` 能列出刚出的图并重新发送。

## 7. 常见故障

| 现象 | 优先检查 |
| --- | --- |
| 机器人搜不到或无法加入群 | 应用是否已发布、可用范围是否包含当前账号、机器人能力是否启用。 |
| 本机显示已连接，但群里 `@` 它没有反应 | `im.message.receive_v1` 是否已添加；是否选择长连接；是否发送到唯一绑定群；是否确实 `@` 机器人。 |
| 文字能收发，卡片按钮无响应 | "回调配置"是否选择长连接并订阅 `card.action.trigger`；不要用旧的 `_v1` 回调。 |
| 图发不出去，日志里重试 | 是否开通 `im:resource` 并发布了新版本；图片是否超过飞书的大小限制（10 MB，本项目的图约 1–2 MB）。 |
| 自动绑定到了不该使用的群 | 停止网关，本地修正 `.env` 的 `OOPZ_FEISHU_ADMIN_CHAT_ID`，再重启。首次绑定之后不会自动替换。 |

## 8. 安全与运维边界

- App Secret、OOPZ 登录凭据、群 ID 都属于运行配置，只保存在 `.env` 或服务器的受保护配置目录中。
- 本项目只将一个群设为控制群，但不在群内划分管理员角色。控制群成员的操作权限相同；不要把不应拥有这些权限的人加入。
- 应用更新、权限变更后始终创建/发布新版本，并重启网关以便验证。
- 生产环境的 `.env`、输出、飞书状态和日志属于持久数据，遵守 [部署状态基线](docs/DEPLOYMENT_STATE.md) 的目录与发布规则；不要在服务器版本目录中手改代码或配置。
