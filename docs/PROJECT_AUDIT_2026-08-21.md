# 项目一致性审查（2026-08-21）

## 已修复

- 多管理员：离开指令的发送者取得分析确认权；自动结束仍回到发起者。
- 多步对话：报告与待分析流程按管理员隔离，显式新流程会清理本人旧流程。
- 转写：录音结束后自动重试失败分片；空分片继续使用无文本标记。
- 分析：同一 Session 防止重复启动；待分析入口会清除同 Session 的旧确认请求。
- 报告：按最近生成的分析 bundle 选择，避免旧 `qq_messages.jsonl` 或旧 variant 覆盖新报告。
- 配置：QQ 的分片范围改为与录音器一致的 30–300 秒；新增自动修复次数。
- QQ 自愈：识别“WebSocket 在线但 QQ 账号离线”；修复跨进程复用 monotonic 时间和失败后高频重启。
- 空闲掉线检测：即使没有待发送消息，也每30秒查询一次 OneBot 登录状态，避免 NapCat 被踢后端口仍在线而看门狗误判健康。
- NapCat 恢复：修复父进程退出带走子进程后，恢复脚本把“进程已消失”误判为停止失败、从而没有重新启动的问题。
- QQ 附件：PDF/Markdown 改走 NapCat 专用文件上传动作，绕开成功发送后仍输出 protobuf UTF-8 遥测告警的富消息路径。
- 启动器：等待控制器真实取得实例锁，并仅在确认旧 PID 已失效后清除陈旧锁，避免重启后留下空窗口却没有控制器。
- Unicode：生命周期通知也统一使用安全的 OneBot 文本段。
- 删除：手动 Session 删除前遍历检查链接；Session 清理同步删除归档 PDF。
- Schema：截止默认值更新为 04:00，OneBot 健康状态 Schema 补齐现有字段。
- CLI：默认分析入口改为供应商无关的 `configured-api`，固定 MiMo 路线保留作兼容。
- API 降级：四窗口批量总结若返回缺项、错项或无效 JSON，会自动拆成单窗口重试并在前台显示原因。
- Python 环境：移除无效的 `~opz_voice_capture` 安装元数据残留，`pip check` 恢复无警告。
- 文档：README 和当前规范统一到 300 秒、60 分钟、北京时间 04:00、SenseVoice auto、通用 API 和多管理员逻辑。

## 尚需人工或线上验证

- 制造一个可恢复的转写失败，核对自动修复、音频删除和通知文字；

- 更换一个非 OpenCode 的兼容 API，验证 JSON mode/thinking mode 组合。

## 后续优化建议

1. 把 1800 行以上的 `qq_controller.py` 拆成状态机、报告投递、设置和录音监督模块，降低回归风险。
2. 为控制器、录音器、分析器增加统一的事件日志文件与关联 ID，替代部分散落 JSON 状态。
3. 增加端到端故障注入测试：断网、API 429、NapCat 掉线、磁盘不足、PDF 渲染失败。
4. 增加磁盘余量预检；录音前不足阈值时拒绝启动并通知管理员。
5. 将外部 API 模型能力做成配置探测（JSON mode、thinking 参数、上下文上限），首次使用时自动给出兼容性报告。
6. 在云服务器部署前改用服务管理器，并把 QQ、录音、分析拆为独立进程；当前控制器内启动录音的模式适合本地 POC，但控制器自身退出会影响其子任务。
