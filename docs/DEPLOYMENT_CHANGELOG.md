## 待发布

### 2026-08-27 — 分析异常退出的断点恢复

- 类型：运行可靠性与飞书会话可发现性修复。
- 运行变化：网关启动时检查未完成分析的锁文件；仅锁内 PID 已不存在且路径安全时才回收锁，并把分析生命周期写为“中断可恢复”。恢复入口会重新出现在“待分析”和“删除会话”，状态查询会提示恢复操作；存活 PID 的任务不被抢占。
- 数据与迁移：不改变 `.env`、报告格式或已有检查点。恢复分析复用已落盘的短/长窗口摘要，只请求缺失阶段；无需迁移或清理会话数据。
- 部署步骤：安装发布包后重启飞书网关。重启完成后检查“状态”，再通过“待分析”恢复中断会话；尚未完成的会话在恢复前不会出现在 PDF/完整报告列表。
- 回滚：回滚代码不会删除会话或检查点；但旧版本不会自动释放异常退出遗留的锁，必要时应先停止相关进程再按新版本恢复。
- 验证：覆盖死锁可见与回收、存活锁保护、启动后状态恢复和待分析卡片提示；完整测试 `165 passed, 1 skipped`。

### 2026-08-23 — 分析 API 配置改为全量显式必填

- 类型：生产配置契约与启动校验。
- 运行变化：生产网关启动时必须读取完整的 `ANALYZER_PROVIDER`、API Key、Base URL、模型、超时、重试、请求间隔、普通/思考 Token 上限、思考模式和 JSON 模式；任何一项缺失都会拒绝启动，不再按供应商补全地址或模型，也不再补全运行参数。
- 推荐方案：当前推荐 OpenCode Go + `mimo-v2.5`，现有实测中成本较低、总结效果较好；它只作为文档建议，价格和可用性需在部署时确认。300 秒窗口默认 4 路并行不变。
- 配置迁移：部署新版本前，按 `.env.example` 检查服务器持久配置并显式填写全部 11 个 `ANALYZER_*` 项；不得把实际密钥写入仓库或发布包。无需迁移会话、模型或飞书状态数据。
- 部署步骤：先补齐服务器共享 `.env`，再安装发布包并重启网关；通过启动日志和一次受控分析确认所选供应商与模型可用。
- 回滚：回滚应用代码可恢复旧默认行为；建议保留已显式填写的配置，回滚不需要恢复持久数据。
- 验证：分析配置缺项、端点/模型无回退、设置状态与生产启动失败均有测试覆盖；完整测试 `162 passed, 1 skipped`。

### 2026-08-23 — 飞书卡片提示统一为按钮交互

- 类型：运行时交互修复。
- 运行变化：分析确认卡移除“回复：是 / 否”，录音目标卡移除“回复编号”并提供取消按钮；旧控制器文案在飞书出口统一转换。
- 配置与数据迁移：无；`.env`、会话目录和飞书状态格式不变。
- 部署步骤：随下一发布包更新代码并重启飞书网关。
- 回滚：回滚代码即可；不涉及持久数据恢复。
- 验证：自动化覆盖长句适配、Outbox 卡片和选择取消交互；完整测试 `160 passed, 1 skipped`。

### 2026-08-22 — 服务器自动获取开源语音模型

- 类型：紧急部署流程修正，应用版本提升至 `0.11.2`。
- 模型来源：魔搭社区官方 `iic/SenseVoiceSmall`，Apache-2.0；默认固定审核过的模型修订版，不跟随浮动 `master`。
- 安装变化：首次部署由服务器自动下载约 0.94 GB 模型并校验 5 个必需文件的 SHA-256；成功后在共享模型目录保存 `MODEL_SOURCE.json`，后续版本复用。
- 失败策略：模型下载失败、文件缺失或哈希不一致时中止安装，不切换 `current`；已存在但无效的模型目录不会被自动删除或覆盖。
- 发布包校验：构建时统一使用 ZIP 标准 `/` 路径，并强制确认安装脚本、模型下载器和发布清单存在；发现运行目录或敏感内容时拒绝产出正式包。
- 服务器要求：必须允许出站访问 `modelscope.cn`，无需再从开发机复制模型。
- 数据迁移：无。已有且哈希一致的模型只补写来源清单；生产配置、会话数据和飞书状态不变。
- 回滚：代码可回滚；共享模型不随代码回滚。更换模型修订版必须另行提供兼容与恢复说明。
- 验证：固定修订版可由 ModelScope 精确下载；下载器单元测试、完整 pytest、发布审计和新 Release 哈希校验。

### 2026-08-22 — 建立云服务器发布基线

- 类型：部署流程。
- 代码/配置影响：新增基于干净 Git 提交的发布包、SHA-256 校验、版本目录、共享持久目录、健康检查和回滚约定。
- 发布审计：新增 `.codex/release-audit-baseline.json`，复用已人工确认的敏感词误报位置；每次提交/发布生成不含匹配文本的内部审计日志，新命中会阻止发布。
- 部署文档：新增根目录 `README_CLOUD_SERVER_DEPLOYMENT.md`，记录私有 GitHub 认证、Release 下载、持久目录、配置/模型准备、安装、验证、自动启动、更新与回滚的完整 Windows 云服务器流程；纳入飞书机器人从零配置说明。
- 交付方式：正式包使用 GitHub Release 同时发布 ZIP 与 SHA-256；服务器按 Release ID 下载，避免直接跟随可变化的 `main`。
- 服务器操作：首次建立 `C:\OOPZ` 目录结构，准备生产 `.env` 与模型，安装 Python 3.12、Node.js LTS 和 Chrome/Edge。
- 数据迁移：无；首次部署时由服务器下载并校验模型，同时创建空的输出/状态/日志目录。
- 回滚：首次部署无旧版本可回滚；后续版本保留上一发布目录。
- 验证：完整 pytest、发布包哈希、进程存活、飞书长连接日志及一轮端到端业务验证。
- 对应提交：飞书迁移基线 `cdfe7408e8ae011e9897ab95fbde3035754b769a` 与本条更新所在提交。首个 GitHub Release ID 由该提交的 `RELEASE_MANIFEST.json` 记录。
