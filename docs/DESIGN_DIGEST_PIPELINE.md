# 录音 → 自动分析 → 精华图 → 飞书群：设计与实现

本文描述 Linux 主线的分析与出图实现（2026-10-03 起，0.13.x 稳定运行）。它取代 Windows 版"分析 → 群内审核 → 批准发布到飞书文档/Base"的流程；旧流程只保留在 `windows-legacy`。

## 目标

```text
飞书群 @机器人「开始录音」
  → OOPZ 录音 + 分片转写（含出入频道记录与头像）
  → 手动「结束录音」或自动退出（无人 / 断线 / 到点）
  → 自动分析（Qoder CN CLI）→ 受校验的内容 JSON
  → 渲染 digest.png（+ digest.md）
  → 飞书群依次收到图片、digest.md（图片上的文字稿）、一条分析用量文本
  → （可选）图片经 MaiBot 本机接口发到 QQ 群（见 [QQ 发图](QQ_BRIDGE.md)）
```

没有审核、批准、公开文档、Base 索引、撤回环节。

这张图是**宣传/吸引眼球**用的，不是总结：忽略大部分平淡内容，只留最有梗的几个点，用"标题 + 一句吐槽"。字数不多，不给人认真阅读；**篇幅随录音时长分四档**（见下）。

## 内容结构（图上的区块，自上而下）

| 区块 | 来源 | 说明 |
| --- | --- | --- |
| 固定小标语 + 日期时间 | 模板与运行层 | 不由模型生成 |
| **今日之最：评价** | `odd_topic` + 编辑给的短评价 | 整场最离谱的一个话题；不含昵称 |
| 大家的表现 | `people.profiles`（3～7 条，随录音时长） | 口语称号 + 一句吐槽；只能引用该人自己的发言 |
| 发言频率 | 程序统计（`digest/stats.py`） | 模型不得给数量/排名；缺出入记录时如实写不生成排名 |
| 这场聊了什么 | `moments`（话题怎么一路跑偏，每个 3～4 步，可以没有）、`topics`（必须带昵称） | 每块有编辑给的小角标 |
| 还没聊完的线索 | `next_hooks`（可以没有） | 独立面板，与话题区分 |
| 这场怎么聊下来的 | 各窗口的时间范围 + 编辑写的短标题 | 最后一块，卡片网格 |

没有"总览"：模型不再生成总览，卡片也不显示（大标题改为固定小标语）。

### 篇幅随录音时长

按录音总时长分四档，上限由程序强制（`analyzer/pipeline.py` 的 `TIERS`），最终汇总的提示词里也带着同样的数字；条目不够好就少写，可以为空：

| 录音时长 | 话题 | 名场面 | 悬念线索 | 人物 | 每条正文字数 |
| --- | --- | --- | --- | --- | --- |
| ≤ 2.5 小时 | 3 | 1 | 1 | 4 | 400–700（整张图） |
| ≤ 5 小时 | 4 | 2 | 2 | 5 | 550–950 |
| ≤ 9 小时 | 5 | 3 | 2 | 6 | 700–1200 |
| 更长 | 6 | 4 | 3 | 7 | 850–1450 |

最长一档合成海报约 10600px，低于 12000px 的画布上限。

## 数据契约

- 模型只产出 `oopz.digest.content.v2`（`content` + `people`）。每条必须带 1–6 个 `evidence_ids` 与一个原文 `anchor`（逐字、4–80 字）；`digest/contract.py` 校验证据 id、锚点、顺序、`speaker_id` 与昵称，并拒绝引号/网址/Markdown、绝对化用词（"最"等）、证据里没有的数字、`odd_topic` 里的昵称。人物条目只能引用该人自己的发言（合计至少 16 字）。
- 统计（发言频率）由程序用出入记录和转写确定性计算，模型不得给出。
- 运行层提供元信息（日期、时间、页脚、时间线、角标）。模型输出里的 SVG/HTML/URL/路径只当文字。
- 叙述规则以 `analyzer/narrative_rules.txt`（V7 规则原文）为基础，`analyzer/prompts.py` 在其上加语气、各阶段的要求和格式约束。

## 分析器（`analyzer/`）

```text
transcript.jsonl → 按说话人合并成连续发言（run，证据 id r0001…）
   → 按字数/静音切成窗口 → 逐窗口出带证据的笔记（并行 3 路）
   → （窗口多于 12 个时先分组合并）
   → 汇总：挑出整场最有梗的点（odd_topic、topics、moments、next_hooks、people）
   → 编辑改写：每条改成"标题 + 一两句吐槽"，同时给角标和时间线短标题
   → 审稿（最多 2 轮）：模型以中文读者的眼光重读自己的全部标题和正文，并逐条对照原文证据核对事实、检查人物卡与主人公是否相关，只改不顺或不符的地方
   → 渲染一次检查是否超高（超高退回缩写）
```

要点：

- **全量、不抽样**：每条发言恰好出现在一个窗口里；失败的窗口记入 `coverage` 并如实在页脚说明，不会静默消失。
- **说话人别名**：给模型看 `s1…sN`，不暴露 32 位十六进制 id；昵称按名单原样引用。
- **机械校验 + 带位置的重试**：同一个校验器检查窗口笔记、合并结果、汇总、改写；被拒绝时把全部错误（带位置、详细原因）一起反馈，最多 4 次。
- **风格检查**（程序强制）：各区块条数不超过本场档位的上限；人物不得是"未识别成员"；话题和转场的标题或正文必须含昵称；转场步骤 ≤4 个、每步标签 ≤7 字；超过 15 字的正文必须有标点；改写不得把话题或人物删到少于 3 条（草稿本来更少除外）。
- **去重**：话题、名场面、人物卡、今日之最里，两块引用的原话重合过半就视为同一件事，只保留一块（悬念线索除外）；最后一次尝试由程序按优先级自动去掉重复项。
- **标题规则**：汉字不超过 12 个，标点和空格不计，允许任何标点（引号、书名号除外）；要抓眼球、可以跳脱，但必须是通顺的一句话；标题里至少要有一个来自这件事原话或草稿的两字词，防止凭空造词。
- **容错**：程序补全机械性缺项（未知证据 id、阶段图标类别等）；JSON 取第一个完整对象，并救回写在根对象之外的 `labels`。
- **转写错字**：不做单独的纠错调用，只在提示词里要求先结合上下文判断、没把握的不写。因此不同次运行会挑不同的点，这是已知的限制。
- **审计与用量**：`calls.jsonl` 记录每次模型调用（阶段、耗时、输入/输出字数、CLI 返回的用量、错误、被拒绝的原文），`windows.json` 是各窗口结果；失败时 `failure.json`。免费模型的 token 与费用字段恒为 0，所以飞书里的用量文本只给模型名、请求次数（含因校验未通过的重试次数）和耗时。

## Qoder CN CLI 后端（实测事实）

- 路径：`/opt/oopz/shared/tools/qodercn-1.1.65/node_modules/.bin/qoderclicn`，运行用户使用独立 HOME（保存登录，须在 `/opt` 下，`ProtectHome` 挡 `/home`）；免费额度。
- 无头调用：`-p`、`--tools ""`（纯文本补全）、`--no-session-persistence`、`--output-format json`、`--system-prompt`、`-m Qwen3.8-Flash`；用户消息从 stdin 传入。`--thinking enabled` 必须同时给 `--thinking-budget`，本项目不用思考模式。
- 单次调用约 25–280 秒；3 路并行可行；空结果视为失败并重试。

## 渲染（`digest/render/`）

离线 Pillow 渲染，固定画布 1080 宽、高度上限 12000；视图（view）是单一事实来源，PNG 与 Markdown 由它生成，两者文字逐块一致（有测试）。字体不入 Git，`scripts/download_fonts.py` 按固定 URL 与 SHA-256 下载，`OOPZ_FONT_DIR` 指定目录。

## 已知限制与待办

- 语音识别错字使挑选不稳定；需要稳定性时可考虑转写清洗，目前按用户决定不做。
- 出入记录、头像下载和身份映射见 [架构](CURRENT_ARCHITECTURE.md)；已在真实录音中验证。
- 同一场录音每次分析挑出的点会略有不同（模型输出有随机性）；"事实核对"依靠审稿这一步和证据校验，不是形式化证明，偶尔会有夸张的措辞。
- 见 [项目状态](PROJECT_STATUS.md) 的待办顺序。
