# QQ 发图（外挂模块）

录制、分析器、飞书网关之外的第四个模块：录音分析出图后，把同一张图发到一个 QQ 群。它只读成品图，经同一台服务器上 MaiBot 的 `ling_relay` 插件（本机接口 `127.0.0.1:18764`）发送；对 OOPZ 和飞书一无所知，也不改 MaiBot 的任何文件。

- 代码：`src/oopz_capture/qq_bridge/`（`relay.py` 接口客户端与重试规则，`deliver.py` 一次发送与飞书通知）。控制器里只有一处调用（`controller._analyze_and_deliver`），设置里只列了三个本机变量名。
- 接口说明在仓库 `XK205E3n/maibot-ling` 的 `plugins/ling_relay/README.md`；本模块按其契约实现。

## 配置（只写在服务器 `shared/config/.env`，不入库）

| 变量 | 说明 |
| --- | --- |
| `OOPZ_QQ_GROUP_ID` | 目标 QQ 群号。留空 = 整个模块关闭，行为与没有它时完全一样 |
| `OOPZ_QQ_RELAY_TOKEN` | 接口口令，取自 MaiBot 的 `plugins/ling_relay/config.toml` 的 `[api] token`，原样复制 |
| `OOPZ_QQ_RELAY_URL` | 可选，默认 `http://127.0.0.1:18764`；只接受本机回环地址，口令不会发到别处 |

口令必须放进 `.env`：服务带了 `ProtectHome`，读不到 `/home/ubuntu/MaiBot/...`。口令不会进日志、`qq_relay.json` 或飞书消息；设置状态只列变量名。

启用前提：MaiBot 后台已打开"外部发图接口"并设了口令；目标群不在"不发的群"黑名单里；机器人在这个群里；图片位于允许读图的目录（默认 `/opt/oopz/shared`，本模块总是传解析过符号链接的真实路径）。

## 行为

- 时机：飞书那三条（图、`digest.md`、用量文本）排队之后，才发 QQ。"重新出图"也会再发一次。只发图，不带文字。
- 发送编号：`oopz-<会话ID>-<图片内容前 8 位哈希>`。同一张图的重试是同一个编号（接口会识别为重复、不重发）；重新出的图是新的编号。
- 结果处理（按接口约定）：
  - `sent`：完成。
  - `failed`、连接被拒绝：同一编号重试，最多共 4 次，间隔 5/15/30 秒。
  - `429`：按返回的 `retry_after` 等待后重试。
  - `unknown`、`partial`、请求超时：**不重试**，飞书群里发一条文字请人工到 QQ 群确认。
  - 其他 4xx/5xx（黑名单、未启用、口令错、找不到会话等）：不重试，飞书群里发一条文字说明原因。
- 成功时飞书里不提；只有需要人处理时才发一条文字。QQ 的任何问题都不影响飞书发送和本次分析的结果。
- 每次结果写入会话目录 `analysis/qq_relay.json`（含状态、次数、编号、群，不含口令），随会话 30 天后一起删除。日志里有一行 `[QQ发图] …`。

## 排查

| 现象 | 常见原因 |
| --- | --- |
| 飞书群提示"在 MaiBot 的黑名单里" | 到 MaiBot 后台把这个群从"不发的群"里去掉 |
| "MaiBot 的外部发图接口没有启用" | 后台打开"启用外部发图接口"并设口令 |
| "发图口令不对" | `.env` 里的口令与 `config.toml` 不一致 |
| "找不到这个群的会话" | 机器人不在群里 |
| "连不上 MaiBot" | MaiBot 没起来，或端口改过（改 `OOPZ_QQ_RELAY_URL`） |
| "结果不确定" | 先到 QQ 群看是否已有这张图，不要重复发 |
